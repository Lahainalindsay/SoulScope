## 2. Sensitive Files — Findings & Actions

### `frontend/.env.local` — REMOVED from tracking

**Issue:** A real environment file was committed and tracked. It contained:
- `NEXT_PUBLIC_SUPABASE_URL` — the live Supabase project URL (`jhamqpfxblybshjmgvsy.supabase.co`)
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` — value was a placeholder (`******`), not a real key

**Action taken:** `git rm --cached frontend/.env.local`

**File status:** The file still exists on disk locally (untouched); it is only removed from tracking. It will not be committed again because `.gitignore` already contains `*.env.local`.

**History note:** This file appears in commits `82201eb`, `6410db0`, and `a11145b`. The Supabase project URL (`jhamqpfxblybshjmgvsy.supabase.co`) exists in git history. Because the anon key value in history is a placeholder rather than a real credential, no immediate history rewrite is required. However, if a real anon key is ever placed in this file and committed, `git-filter-repo` should be used immediately to purge it.

### `supabase/.temp/` — REMOVED from tracking (9 files)

**Issue:** Supabase CLI generates a `.temp/` directory containing project metadata including:
- `project-ref` — the Supabase project identifier (`jhamqpfxblybshjmgvsy`)
- `pooler-url` — a full database connection string including host (`aws-0-us-west-2.pooler.supabase.com`)
- Version pins for CLI, GoTrue, Postgres, REST, storage

These are local working files generated by `supabase link` and should never be committed.

**Files removed from tracking:**
```
supabase/.temp/cli-latest
supabase/.temp/gotrue-version
supabase/.temp/pooler-url
supabase/.temp/postgres-version
supabase/.temp/project-ref
supabase/.temp/rest-version
supabase/.temp/storage-migration
supabase/.temp/storage-version
```

**Action taken:** `git rm --cached -r supabase/.temp/`

**History note:** `supabase/.temp/pooler-url` and `supabase/.temp/project-ref` exist in git history. These contain the Supabase project reference and database pooler URL. These are not credentials (no password), but they do expose infrastructure details. If the project is made public, consider running `git-filter-repo` to purge `supabase/.temp/` from all history.
