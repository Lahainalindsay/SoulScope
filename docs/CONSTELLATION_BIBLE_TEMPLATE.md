# SoulScope Constellation Bible

## Purpose

The Constellation Bible defines the human meaning, geometry, boundaries, confidence rules, narrative language, and visual behavior of every constellation state before that state is implemented in code.

It is the source of truth for the reasoning engine. Code should implement the Bible; the Bible should not be reverse-engineered from whatever the code happens to produce.

## How to use this document

Complete one full section for each constellation:

1. Cognitive
2. Energy
3. Expression
4. Resonance

Then complete the Cross-Constellation Interaction section.

Do not start by writing pattern names. Begin with the four inputs, define what each one means, decide how they interact, map the meaningful regions, and only then name the states.

# Cross-Constellation Interaction Bible

After all four constellation state maps are complete, define how their outputs interact.

## Interaction families

For each family, define what it means and which constellation combinations support it.

### Reinforcement

Two or more constellations point toward the same lived pattern.

### Compensation

One constellation is carrying or stabilizing strain in another.

### Contradiction

Constellations point in different directions, creating mixed experience or internal friction.

### Resource cost

A strong cognitive or expressive state is being maintained at an energy cost.

### Protection

Reduced openness or activity appears to be serving regulation or preservation.

### Momentum

Direction, energy, and expression support forward movement.

### Transition

The current scan differs meaningfully from the person's established signature.

### Integration

Several systems are working together with relatively low internal friction.

# Narrative Writing Rules

1. Write to the person as “you.”
2. Describe recognizable experiences, not abstract system labels.
3. Avoid “your cognitive state suggests,” “the data indicates,” and similar clinical openings in the user-facing reflection.
4. Do not force positive language onto difficult scans.
5. Do not make difficult scans sound hopeless or fixed.
6. Include strengths and costs when both are present.
7. Prefer “may,” “can,” “appears,” and “you might notice” when certainty is limited.
8. Never diagnose, moralize, accuse, or infer deception.
9. Keep the pattern name secondary to the actual reflection.
10. Every statement must be traceable to constellation or evidence support.

# Acceptance Checklist

A constellation is ready for implementation only when:

- all four inputs are fully defined
- geometry and interaction rules are explicit
- clear states are mapped
- transitional and boundary blends are mapped
- unresolved behavior is defined
- every state has daily-life examples
- every state has reflection questions
- support and contradiction rules exist
- confidence limits are defined
- visual behavior is defined
- language has been reviewed for warmth, realism, agency, and non-diagnostic framing
